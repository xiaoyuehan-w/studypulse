# StudyPulse 数据契约（冻结）

> **冻结日期**：2026-09-24（hub Issue #45 推送根治任务 A.5）
> **为什么冻结**：2026-09-24 PARA 迁移改动 vault 目录后，手机上的旧 APK 仍硬编码旧路径
> `03-规划/周计划` → `getLatestWeeklyPlan()` 返回 null → 永不重新调度 → 每日推送失效。
> 本文件把 App 依赖的读取契约写成单一事实源：**改契约 = 必须配套 App 发版 + 用户重装 + 重新同步一次计划。**

---

## 一、契约内容

### 1. 仓库与路径（vault：learning-system）

| 用途 | 路径 | 代码位置 |
|------|------|---------|
| 周计划目录 | `10 项目/考研科软/周计划` | `lib/services/github_service.dart` → `listWeeklyPlans()` |
| 学习状态文件 | `10 项目/考研科软/学习状态-共同.md` | `lib/services/github_service.dart` → `getLearningStatus()` |

> vault 目录经历过三代：重构前结构（`03-规划/…`）→ 英文 PARA → 中文 PARA（现行）。
> 迁移/改名时必须 grep 全部代际名字（hub `lessons.md` L7）。

### 2. 文件名规则

```
周计划-第N周-YYYY.M.D.md      例：周计划-第1周-2026.9.23.md
```

- App 用正则 `(\d{4})\.(\d{1,2})\.(\d{1,2})` 从文件名提取日期并**降序排序**，第一个即最新计划。
- 月份/日期**不补零**也能解析（`2026.9.23` 与 `2026.09.23` 均可，但请保持一种写法）。
- 文件名无法解析日期的文件排序置底，不会破坏最新计划的识别。

### 3. 文件内 Section 结构（缺 Section 不报错，但对应内容为空）

| Section | 作用 |
|---------|------|
| `# 第N周（YYYY.M.D - M.D）` | 周标签 + 日期范围；缺失时回退读 YAML `week:` 字段 |
| `## 每日安排` | markdown 表格：首列 `周X`（可带 `M.D`），其余列 = 科目 → 任务内容 |
| `## 本周章节目标` | markdown 表格：`科目` 列 + 内容列 |

- 任务内容中的 `[[链接]]` 会被剥壳为纯文本；`不动`、`—`、空 = 当天无任务、不推送。
- 单元格内的 `|` 会破坏表格解析，请避免。

---

## 二、改动规则（红线）

1. **任何一项契约变更**（路径 / 文件名规则 / Section 名 / 表格结构）：
   - 必须同一个 PR 内同步 App 代码 → 走 studypulse PR + CI 三件套
   - 合并后**必须发新版本 APK**，并通知用户重装 + 打开 App 同步一次
   - 看板条目 + 日报记录在案
2. **只新增 `30 资源/` 内容层笔记**（含外部参考 submodule）：不影响契约、不影响推送——App 只读上表两个路径。
3. vault 侧编辑周计划时只改表格内容，**不删改 Section 标题与列结构**。

## 三、推送健壮性约定（2026-09-24 起）

- App 启动即后台同步并调度（`PlanSyncService`），不依赖首页是否打开。
- GitHub 拉取失败/断网/未配置 → 用本地缓存（`latest_weekly_plan.md`）调度。
- 重启手机 / 覆盖安装 APK → manifest 里的 `ScheduledNotificationBootReceiver`
  自动重排（BOOT_COMPLETED / MY_PACKAGE_REPLACED / QUICKBOOT_POWERON）。
- Android 12+ 精确闹钟未授权 → 自动降级非精确（可能延迟 ≤15 分钟），设置页可授权。
