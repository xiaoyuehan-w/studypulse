# StudyPulse 重写方案 v2

> **决策**：不修补，**从零重写**。理由与代价见下，先给结论：这个 App 只有 **2732 行 / 11 个文件**，重写的技术风险可控；而继续修补的风险更高。

---

## 一、事实基线（重写前先看数）

| 项 | 现状 |
|---|---|
| 代码量 | **2732 行 / 11 个 Dart 文件**（最大：`home_screen.dart` 663 行） |
| 测试 | 259 行 / 3 个文件（契约解析、同步、统计） |
| 依赖 | 10 个（http · flutter_local_notifications · timezone · flutter_timezone · shared_preferences · path_provider · intl · flutter_markdown · url_launcher · flutter_foreground_task） |
| 代码来源 | 首版设计成型于 2026-09-21（系统尚不存在），此后经 **4 个不同 AI、7 次 PR** 叠加修补 |
| 包名 | `com.studypulse.studypulse`（**保持不变 → 覆盖安装、不丢配置与缓存**） |

## 二、为什么要重写（三条硬理由）

1. **原始设计已作废**：首版按"App 写 JSON + GitHub Actions 汇总"设计（当时的方案 B），而现在的数据来源是 vault 里的周计划 markdown —— 现有代码是在**过时的数据模型上打的补丁**。
2. **无完整心智模型**：4 个 AI 轮流改，每个人只掌握自己那一块；最近的故障（首页空白、静默失败、副作用阻断）都源于"没人看清整体"。
3. **产品定义已更新**：`docs/产品再设计-v1.md` 把 App 从"每日提醒工具"重新定位为**执行终端**（今天做什么 → 打卡 → 周日复盘）——这需要重新组织界面与数据流，不是补丁能达成的。

**同时必须承认的代价**（不粉饰）：
- 需**你装机验证 3 轮**（每阶段一轮），这是唯一的外部验收，无法由我代替
- 真机相关行为（通知、前台计时、开机自启）在重写后需重新确认一遍
- 兼容性风险：若中途发现新版本某个能力不如旧版，**旧版 APK 保留可随时回滚**

## 三、重写不变量（红线，重写不等于放飞）

| 不变量 | 说明 |
|---|---|
| **数据契约冻结** | 路径 `10 项目/考研科软/周计划`、文件名 `周计划-第N周-YYYY.M.D.md`、section `## 本周章节目标` / `## 每日安排` ——**一字不改** |
| **只读不写** | App 永不写回 vault；完成状态只存本地 |
| **包名与签名不变** | 覆盖安装不丢 Token/缓存 |
| **缓存优先** | 先渲染缓存再后台同步；离线可看今天 |
| **失败必可解释** | 每步失败给「哪一步 + 原因 + 你该怎么办」 |
| **依赖不增加** | 沿用现有 10 个依赖；不引入状态管理库（保持轻量可控） |

## 四、架构（4 层，简单到能一眼看懂）

```
lib/
├── models/          纯数据模型 + 契约解析（无 IO，可单测）
│   ├── weekly_plan.dart      周计划模型 + parse（从旧代码移植测试用例）
│   └── progress.dart         本地进度模型（打卡/时长/完成率/连续天数）
├── data/
│   ├── github_source.dart    GitHub 读取（内容接口 + 自查 + 错误分类）
│   └── local_store.dart      本地存储（Token/设置/缓存/进度）
├── services/
│   ├── sync_service.dart     同步编排（缓存优先 + 失败分类 + 自愈调度）
│   ├── notify_service.dart   每日推送（自愈 + 开机重排 + 权限体检）
│   └── timer_service.dart    学习计时（开始时间戳为唯一事实源）
└── ui/
    ├── today_page.dart       今日（三块 + 打卡 + 计时 + 完成率行 + 作息提醒）
    ├── plan_page.dart        计划（章节目标 + 7 天 + 验收清单打勾 + 周日复盘卡片）
    ├── stats_page.dart       统计（时长 + 完成率 + 连续天数）
    └── settings_page.dart    设置（GitHub 配置 + 自查 + 推送时间 + 权限体检 + 缓存）
```

## 五、从旧代码**带过来**的东西（这才是重写的价值：不重踩坑）

| 旧代码里的资产 | 处理 |
|---|---|
| 契约解析（正则 + 表格解析，含"不动/—"豁免规则） | **移植并补测试**（旧代码已踩过格式坑） |
| 通知调度策略：启动自愈 + 开机重排 + 权限体检 + 缓存兜底 | **整套移植**（PR #7 的成果，真机验证过） |
| `flutter_local_notifications` 17.x 的 receiver 必须 App 自己在 manifest 声明 | 保留（否则推送静默失效） |
| 计时以"开始时间戳"为唯一事实源（杀进程不丢时长） | **照搬设计** |
| 中文字体/图标 tree-shaking、debug 签名覆盖安装 | 保留 |
| 错误分类与自查（仓库 200 / 目录 404 / Token 长度判型） | 移植为 `github_source` 的自查能力 |

## 六、分阶段（每阶段都能构建 + 装机验证）

| 阶段 | 内容 | 我出什么 | 你做什么 |
|---|---|---|---|
| **S1 骨架 + 数据层** | 项目结构、契约解析（含测试）、GitHub 读取 + 缓存优先 + 自查、今日/本周两屏（只读展示） | 可安装 APK | 装一次 → 确认能看到今天三条任务 |
| **S2 执行闭环** | 打卡、计时（时间戳）、完成率、连续天数、验收清单打勾、统计页 | APK | 装一次 → 打卡 + 计时 + 看统计 |
| **S3 通知与复盘** | 每日推送（自愈/开机重排/权限体检）、周日复盘卡片、周报草稿一键复制、设置页完善 | APK | 装一次 → 验证推送与复盘 |

## 七、时间与节奏（诚实预估）

- 代码我可以连续写：**S1 约 1 次工作会话**，S2/S3 各约 1 次
- **真正的瓶颈是你的装机验证**（每阶段一轮，约半天），所以整体 2-3 天，取决于你验证的快慢
- 每阶段结束我出：APK + 验收清单 + 回滚方式（安装前旧 APK 保留）

## 八、回滚与安全

- 新代码在分支 `v2/rewrite` 上开发，**main 保持现状可发布**
- 旧 APK 保留在 `04-交付物/`：`StudyPulse-v1.1-推送根治版.apk`、`StudyPulse-v1.1-首页加固版.apk` —— 新版不满意随时回装
- 每阶段打 git tag，出问题可回到上一阶段
- 新版本通过 S3 验证后，才归档旧代码与旧 APK
