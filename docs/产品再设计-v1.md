# StudyPulse 产品再设计 v1

> **为什么重做**：现有 App 的产品设计成型于 2026-09-21，那时系统还不存在——没有 PARA、没有数据契约、没有《学习计划·母版》、没有单执行主体。
> 结果是：App 与"每天怎么学、周日怎么复盘"脱节，且失败时只给一句含糊提示（#47 那次排查之痛的根源）。
> 本次**重新定义产品**，让 App 成为新系统的执行终端。

---

## 一、定位（一句话）

**App = 执行终端**：手机上的「今天做什么 → 打卡 → 周日复盘」。
**不是**：第二大脑（知识在 vault）、不是规划工具（规划在主 AI）、不是 AI 助手（AI 是主 AI）。

| 角色 | 承载 |
|---|---|
| vault（记忆层） | 知识、规划、状态——唯一事实源 |
| **App（执行层）** | **今天做什么、做了多久、连续几天、周日复盘** |
| 主 AI（策略层） | 生成周计划、按数据调整、出周报 |

## 二、唯一核心闭环

```
早上打开 → 看到今日三块 → 学习时打卡/计时 → 完成打勾 → 周日看完成率 + 复盘 → 主 AI 按数据调下周
```

一切设计围绕这一条闭环。**不服务这条闭环的功能，一律不做。**

## 三、信息架构（4 个 tab）

| Tab | 内容 | 相对现状的变化 |
|---|---|---|
| **今日**（默认） | 日期 + **三块卡片**（主科/编程/英语）：任务文本、开始学习/计时、打勾；顶部一行「第N周 · 本周完成 x/7」；底部一行作息提醒（01:00 前睡） | 新增完成率行、作息提醒；三块对齐《母版》 |
| **计划** | 本周章节目标 + 7 天列表 + **验收清单（可打勾）** + 下周预告 | 验收清单从"只读"变"可勾"；**新增周日复盘卡片**（当周完成率、未完成项、一键复制周报草稿） |
| **统计** | 今日/本周时长 · **完成率** · **连续天数（streak）** | 新增完成率与 streak——把"连续性"变成可见数字 |
| **设置** | GitHub 配置（含**同步自查**）+ 推送时间 + 权限体检 + 缓存管理 + 关于 | 补齐自查与体检（已完成，PR #8 已合并） |

## 四、数据与契约（保持不变，这是稳定的地基）

- **只读** vault 的两个位置：周计划文件（`## 本周章节目标` + `## 每日安排`）、`学习状态-共同.md`（预留，暂未用）
- **绝不写回 vault**（写回会造成冲突并破坏契约）；App 的完成状态只存本地
- 周计划文件新增 section 必须是**可选 + 向后兼容**（App 忽略看不懂的内容）
- 路径/文件名/section 名**冻结**；变更须配套发版 + 重装（见 `docs/数据契约.md`）
- 三周滚动窗口（`周计划/待启用/`）由主 AI 维护，App 无感

## 五、可靠性原则（针对本次之痛的硬性要求）

| 原则 | 具体做法 |
|---|---|
| **失败必可解释** | 任何一步失败都给：**哪一步 + 什么原因 + 你能怎么办**（例：仓库 200 但目录 404 → "Token 缺文件读权限，去设置点自查"） |
| **缓存优先** | 先渲染缓存（离线可看今天），再后台同步；同步失败不覆盖已显示内容 |
| **只读不写** | 不在手机上改 vault，避免冲突 |
| **副作用不阻断显示** | 计时/通知排程失败不得影响任务显示（已修） |
| **按日期选本周** | 计划文件与"今天"不匹配时明确提示，不再静默空白（已修） |

## 六、分期实施（不推倒重写）

| 版本 | 内容 | 工程量 | 时间 |
|---|---|---|---|
| **1.1.1** | 无新代码：装最新 APK（含按日期选周 + 未更新提示 + 同步自查 + 副作用不阻断） | 0 | **现在** |
| **1.2** | 完成率 / streak / 验收清单打勾 / 周日复盘卡片 / 周报草稿一键复制 | 1-2 天 | 10 月 |
| **1.3** | 落后·超前提示（用打卡数据计算）+ 计划调整建议 | 1-2 天 | 11 月 |
| **2.0** | 桌面端 | — | **暂缓**（规划在主 AI 侧更顺，桌面端目前是伪需求） |

## 七、明确不做（同样重要）

- ❌ 云端同步 / 账号体系（本地缓存 + GitHub 拉取已够；云端要服务器与费用）
- ❌ App 内嵌 AI（AI 就是主 AI，App 只出数据）
- ❌ 多用户 / 社交 / 主题商店 / 花哨动效
- ❌ 在手机上编辑 vault 内容
- ❌ 新增推送类型（每天 8:00 推当天任务已够；多一类多一片 bug）

## 八、验收标准（产品层面）

1. 每天打开 1 次能看到今天的全部任务（离线也能看）
2. 打卡 ≤ 2 次点击；计时不因杀进程丢失
3. 周日复盘可在一处完成（看完成率 + 勾验收清单 + 复制周报草稿）≤ 3 分钟
4. 任何失败都给出可读原因与下一步动作
5. `flutter analyze` 0 issue、test 全过、release build 成功
